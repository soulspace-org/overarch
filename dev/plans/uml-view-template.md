# Plan: UML view template (`templates/views/uml-view.puml.cmb`)

## Goal

Replace the Clojure PlantUML UML renderer
(`src/org/soulspace/overarch/adapter/render/plantuml/uml.clj`) with a template,
so users can customize the UML diagram generation without changing the
Overarch code.

The template renders the view types handled by `:uml-view` in the Clojure
renderer: code views, state machine views and use case views.

## Current state

- `templates/views/uml-view.puml.cmb` exists as an unfinished draft. It has the
  maps, `render-name`, `render-type`, `render-title` and a stub `defmulti`,
  and ends with `' TODO render root elements`.
- `templates/lib/plantuml.clj` has `alias-name`, `short-name`, `render-title`
  and `render-skinparams`.
- `templates/lib/plantuml/uml.clj` is an empty namespace stub.
- The `:uml-view` entry in `templates/gencfg.edn` is commented out (`#_`).
- `collapsed?` has been added to `model-api` (done, see below).

## Problems in the draft

1. It uses the aliases `el/`, `model/` and `puml/`. The template engine only
   provides `m`, `v`, `str`, `sstr` and `set` (`comb.clj`, `sci-opts`).
   `model` is a data binding (the model map), not a namespace alias.
2. `el/collapsed?` was missing in the template API. **Done:** `m/collapsed?`
   added to `model_api.clj`.
3. `render-title` and `render-skinparams` duplicate `lib.plantuml`. The local
   `render-skinparams` also references undefined `k` and `v`.
4. `render/indent` is not available in the template engine, so `indent` must
   be defined in a lib namespace.
5. `<%= (when ...) %>` in the header prints empty lines when the condition is
   false. Collect the layout lines in a vector, remove `nil`s and join them.
6. The commented-out `gencfg.edn` entry has to be enabled and its
   `:view-selection` checked against the view types the Clojure renderer
   handles.

## Design

The template stays thin, like `view.dot.cmb`. The logic lives in the lib
namespaces.

### `templates/lib/plantuml.clj` (common PlantUML functions)

- Keep `alias-name`, `short-name`, `render-title`, `render-skinparams`.
- Add `indent`, `linetypes` and `render-layout`.
  `render-layout` returns a vector of the non-nil lines for sketch, layout,
  linetype, nodesep and ranksep.

### `templates/lib/plantuml/uml.clj` (port of `uml.clj`)

- Requires `clojure.string`, `lib.plantuml`, `org.soulspace.overarch.adapter.template.model-api`
  and `...view-api` (full names, aliased `m` and `v`).
- Maps: `directions`, `visibility`, `cardinality`, `layouts`, `hides`,
  `use-case-level->color`.
- Helpers: `render-name`, `render-type` (takes the model explicitly),
  `render-from`, `render-to`.
  `render-from`/`render-to` keep the existing TODO to fall back to a verbatim
  cardinality for non-keyword values.
- `render-uml-element`: multimethod dispatching on `(:el e)` with
  `:hierarchy #'m/element-hierarchy`. Methods return a vector of line strings.
- Methods to port:
  - boundaries and use cases: `:context-boundary`, `:use-case`, `:actor-node`
  - containers: `:package`, `:namespace`
  - classifiers: `:interface`, `:protocol`, `:enum`, `:schema`, `:class`
  - members: `:enum-value`, `:field`, `:parameter`, `:method`, `:function`
  - code relations: `:composition`, `:aggregation`, `:association`,
    `:inheritance`, `:implementation`, `:dependency`
  - use case relations: `:uses`, `:include`, `:extends`, `:generalizes`
  - state machines: `:state-machine`, `:state`, `:start-state`, `:end-state`,
    `:fork`, `:join`, `:choice`, `:transition`
  - fallbacks: `:model-relation` and `:model-element` (prints a warning for
    unhandled elements)
- The container methods (package, namespace, interface, protocol, enum,
  schema, class, state, context-boundary) share the same "header, children,
  closing brace or `{}`" shape. Extract one `render-container` helper taking
  the header string and an optional child sorter.
- Entry point `render-uml-view [model view]` returns the complete line vector.

### `templates/views/uml-view.puml.cmb`

- `(require '[lib.plantuml :as puml])` and `(require '[lib.plantuml.uml :as uml])`.
- Compute the elements as in `uml.clj`:
  `v/view-elements`, then `v/root-elements` on the nodes, then
  `v/elements-to-render` over the root nodes plus the relations.
- Emit `@startuml <view id>`, layout lines, title, skinparams, rendered
  elements and `@enduml`.
- Keep the trailing `' (generated by Overarch with template ...)` comment.

### `templates/gencfg.edn`

Enable the `:uml-view` entry (remove `#_`) and verify the selection.

### Removal of the Clojure renderer

After the output has been verified as equivalent:

- Remove `render-plantuml-view :uml-view` and the `uml.clj` namespace
  (and its require in the render wiring).
- Check whether `puml/linetypes` and other helpers in `plantuml.clj` are still
  used elsewhere before removing them.
- Update the docs (`AGENTS.md`, templates documentation) to mention the
  template.

## SCI risks to check first

The template engine runs on SCI, so verify these early:

- `defmulti` with `:hierarchy #'m/element-hierarchy`. SCI might not resolve a
  var from a `copy-ns` namespace. Fallbacks: `(var m/element-hierarchy)`, or
  dispatching on an explicit parent lookup.
- `defmulti`/`defmethod` in a `lib.*` namespace loaded through `load-fn`
  (memoized, so no reload).
- Whether `m`/`v` aliases resolve inside the lib namespaces. If not, require
  the full namespaces, as `lib/plantuml.clj` already does.
- `alias-name` returns a symbol. Check that `str` handling works in SCI.

## Verification

1. Generate with the new template from the self-models
   (`models/overarch/data-model/`, `models/overarch/use-case/`), which contain
   code, state machine and use case views.
2. Diff the generated `.puml` files against the output of the Clojure
   renderer. They should match except for whitespace and the trailing comment.
3. Cover edge cases: collapsed elements, empty containers (`{}`), elements
   with `:link`, directions on relations, cardinalities, generic and abstract
   classes, stereotypes.
4. Run the test suite after removing the Clojure renderer.

## Implementation notes

All steps were implemented and verified:

- `layouts` lives in `lib.plantuml` (generic PlantUML), `hides` stays in `lib.plantuml.uml`.
- The `:model-element` fallback emits a PlantUML comment line instead of
  printing to stdout (stdout is captured by the template engine).
- `:method` now flattens the rendered parameters (the Clojure version joined
  the single-element vectors with `str/join`).
- Generated diagrams for all 13 UML views of the self-model are identical to
  the output of the Clojure renderer (ignoring blank lines and the footer comment).
  The self-model has no state machine views and no methods with parameters,
  so these paths are covered by the port only, not by the diff.
- Removed `render/plantuml/uml.clj`, its test and its require in `cli.clj`, the
  `:uml-view` hierarchy entries and the UML views in `plantuml-views`.
- `sci/copy-ns` is a macro, so a prebuilt `tools/overarch.jar` does not know
  `m/collapsed?`. The template needs a build that includes the model-api change.
